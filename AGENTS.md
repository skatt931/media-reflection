# Codex project instructions

- Мова спілкування і specs: українська. Технічні терміни й code identifiers можна англійською.
- Це етап обговорення та архітектури. Не створювати production code, інфраструктуру чи підключення до сервісів, поки користувач явно не попросить.
- Перед кожною архітектурною рекомендацією прочитати `README.md`, `docs/conversation-context.md` та всі `specs/*.md`.
- Розділяти **затверджені вимоги**, **пропозиції** та **відкриті рішення**.
- Критерії: найменша постійна вартість, приватність нотаток, найменша експлуатаційна складність, хороша мобільна UX.
- Не вважати, що GitHub це повноцінна БД, або що login UI достатньо захищає статичний сайт.
- Уточнювати точкові технічні рішення перед впровадженням і оновлювати `specs/07-decisions.md` після узгодження.
