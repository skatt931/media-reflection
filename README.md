# Media Reflection

Особиста медіатека в Telegram: надсилаєш посилання, текст чи голосове. Бот підтягує назву, автора й обкладинку зі сторінки, Groq додає тип і теги, ти дописуєш враження. Потім можна шукати по збереженому й експортувати в Obsidian.

Локальний PoC: Node.js 24+, SQLite, long polling. Працює, поки запущений процес. Рішення — у [specs/07-decisions.md](specs/07-decisions.md).

## Запуск

```sh
npm install
npm run setup        # Telegram-токен і твій user ID → .env
npm run setup:groq   # Groq API key: AI-теги, пошук, голосові (необов'язково)
npm run setup:vault  # шлях до Obsidian vault (необов'язково)
npm start
```

Щоб бот стартував при вході в систему й перезапускався після збою:

```sh
npm run service:install                    # або: node scripts/service.mjs install --caffeinate
npm run service:status
npm run service:uninstall
```

Лог сервісу — `data/bot.log`. `--caffeinate` не дає Mac засинати, поки бот працює. Запускай лише один процес бота: або `npm start`, або сервіс. Сервіс запам'ятовує шлях до поточного `node`; після оновлення Node перевстанови його.

Telegram зберігає непрочитані повідомлення до 24 годин, тож надіслане, поки бот вимкнений, обробиться після запуску.

## Користування

Одне посилання на повідомлення. Посилання, сховане під текстом, теж працює. Текст поруч із посиланням стає першим враженням. Переслане повідомлення (наприклад, пост каналу) зберігається як матеріал: його текст не вважається твоїм враженням. Короткий текст (до 80 символів), надісланий протягом 10 хвилин після посилання без коментаря, додається як думка до нього; кнопка «Це окремий запис» це скасовує. Інший текст без посилання стає окремим записом.

Під карткою:

- ❤️ 👍 😐 👎 — реакція одним дотиком, повторний дотик прибирає її. ❤️ — для найкращого, рідко: з цього складається «Улюблене» в підсумках;
- **Додати думку**;
- **На потім** — відкласти на майбутнє; повторний дотик повертає в «Ознайомився» з сьогоднішньою датою;
- **Змінити** — назва, автор, джерело, теги, дата, опис, тип, стан, «Видалити» (з підтвердженням).

Меню змінюють саму картку, нових повідомлень не створюють. Новий запис отримує стан «Ознайомився» з датою надсилання.

**На потім одним словом.** «потім», «на потім», «later» або 🔖 поруч із посиланням (зокрема в полі коментаря при share) чи окремим повідомленням одразу після нього — і запис іде в «На потім», а слово не зберігається як думка. Записи «На потім» не потрапляють у «Без вражень», поки не позначиш їх переглянутими.

**Ресурси** — сайти, до яких повертаєшся: галереї, інструменти, довідники. Головна сторінка будь-якого сайту, Dribbble, Behance, Awwwards, GitHub, Product Hunt, Figma Community стають «Ресурсом» автоматично, решту розпізнає AI або змінюєш вручну. У ресурсу немає стану й дати перегляду, він не потрапляє в «Без вражень» і не нагадує про себе. Теги, думки й реакції працюють як завжди, а пошук знаходить їх за темою («де той сайт із дизайнами?»).

Після думки AI може поставити одне уточнювальне питання. Reply на картку прив'язує текст до неї. `/cancel` або «Скасувати» виходить із діалогу; діалог сам закривається через 30 хв. Та сама URL (без tracking-параметрів) не створює дубль.

**Голосові** розпізнаються через Groq Whisper (`whisper-large-v3-turbo`) і далі обробляються як текст. Бот показує розпізнаний текст. Мова — `VOICE_LANGUAGE` (за замовчуванням `uk`, порожнє значення — автовизначення).

**Підсумок тижня.** Раз на тиждень (`WEEKLY_DIGEST`, за замовчуванням `fri 18:00`, `off` вимикає) бот надсилає одне повідомлення без звуку: скільки збережено й скільки без вражень, і кнопку «Переглянути». Якщо нічого нового не збережено, повідомлення немає. Якщо минулий підсумок не відкривали, бот оновлює його замість нового. Якщо Mac спав, підсумок прийде після пробудження.

**Щоденник.** `/diary` відкриває режим запису: усі наступні тексти й голосові склеюються в один запис, а не потрапляють у медіатеку. Під статусом — «Готово» (або `/done`), «Дата» (сьогодні, вчора чи будь-яка: `05.11.26`, `2026-11-05`) і «Скасувати» (з підтвердженням). Забув натиснути — запис збережеться сам після години без нових повідомлень. Інші команди й кнопки меню працюють, не чіпаючи тексту: він лишається в чернетці, `/diary` продовжує його. Голосове розпізнається лише після кнопки «Розпізнати» (аудіо йде в Groq). Після збереження «Скасувати запис» (з підтвердженням) видаляє запис, зроблений у боті; імпортовані нотатки бот не чіпає. Щоденник не потрапляє в «Без вражень», підсумки й пошук. У підсумку тижня — рядок «Останній запис щоденника — N днів тому».

**Підсумок місяця й року.** 1-го числа (`MONTHLY_REVIEW`, за замовчуванням `10:00`, `off` вимикає) бот надсилає без звуку підсумок минулого місяця, у січні ще й підсумок року. Це одне повідомлення, слайди гортаються ← →: що збережено і як змінився мікс, улюблене ❤️, що сподобалось і які типи заходять найкраще, теми й імена, що зустрічаються в різних типах (гра, серіал, відео), автори, коли ти зазвичай зберігаєш, до чого повертався, стан «На потім». Рік додає помісячну динаміку, перший і останній запис. Порожній місяць не надсилається. Будь-коли: «Бібліотека» → «Підсумок місяця» або `/review`, `/review 2026-10`, `/review 2026`. Усе рахується локально, у Groq нічого не йде.

**Списки** («Останні», «На потім», «Без вражень», «За типом», результати пошуку) — одне повідомлення, яке гортається стрілками ← →. Реакції й зміни працюють прямо в ньому. Reply на список додає думку до показаного запису.

Меню:

- **Бібліотека** — останні, «На потім», без вражень, «За типом» (лише наявні типи з кількістю), підсумок місяця.
- **Запитати** — пошук звичайною мовою: «подкасти про AI, які сподобались», «ресурси для натхнення», далі «а тільки за жовтень». Слова шукаються незалежно від закінчення («штучного інтелекту» знайде «штучний інтелект»). Без Groq працює простий пошук за словами.
- **Експорт** — записує нові та змінені матеріали в Obsidian.

Команди є в меню «/» Telegram: `/help`, `/list`, `/later`, `/reflect`, `/ask <запит>`, `/review`, `/enrich`, `/export`, `/cancel`. `/help` — одне повідомлення з темами (Зберегти, Враження, Пошук, Списки, Підсумки), кнопки міняють текст на місці. `/enrich` дозаповнює до 20 старих записів: метадані сторінки, обкладинку й AI-теги; також переробляє теги записів, оброблених старішою версією AI-запиту.

## Метадані сторінки

Для посилання бот один раз завантажує початок сторінки (до `</head>`, максимум 1 МБ) і бере Open Graph: назву, автора, опис, обкладинку. Для Threads і Instagram назва береться з тексту допису. YouTube — через oEmbed. Короткі share-посилання (як `threads.com/share/…`) розгортаються. Якщо пост уже збережено, повторне share-посилання зливається з ним.

Запит іде з User-Agent `facebookexternalhit/1.1`: так Threads та Instagram віддають превʼю без входу в акаунт. Адреси локальної мережі й localhost заблоковані на кожному redirect. Обкладинка (до 5 МБ, jpg/png/webp/gif) зберігається в `data/covers/` і показується в картці.

## AI

Groq (`openai/gpt-oss-120b`, змінюється через `GROQ_MODEL`) визначає тип, 3–6 тегів (від загального до конкретного; для музики — жанр і настрій), до 8 згаданих назв і одне речення опису українською. AI бачить теги, які вже є в бібліотеці, і бере наявний замість синоніма («штучний інтелект», а не «ai»). Теги зберігаються з пробілами; в Obsidian — з підкресленням, бо там пробіли в тегах не можна. Реакцію не ставить, твій текст не змінює. Назву й автора AI може взяти лише дослівно з даних сторінки, не з твоїх думок; назва зі сторінки має пріоритет. Поле, яке ти змінив вручну, AI більше не перезаписує. Помилки Groq пишуться в консоль як `Groq <запит>: HTTP <код>`, без вмісту.

Що йде в Groq: назва, текст повідомлення, опис зі сторінки, останні 3 враження про запис, голосові записи. Під час пошуку — запит, 3 попередні запити і до 30 записів, що пройшли фільтри (спершу ті, де збіглися слова): назва, тип, автор, теги, назви, короткий опис, 2 останні враження. AI обирає з них і за змістом, навіть без збігу слів. Під час AI-тегування — до 80 наявних тегів. Вся база й vault не передаються.

Якщо Groq недоступний, запис усе одно зберігається.

## Obsidian

Експорт запускається лише вручну («Експорт» або `npm run export:vault`) і пише у `$OBSIDIAN_VAULT_PATH/Медіатека/`:

```text
Медіатека/
  Медіатека.md                 огляд: останні, на потім, улюблене, сподобалось, ресурси, без вражень
  Матеріали/<назва> — <id>.md  одна нотатка на матеріал
  Обкладинки/<id>.jpg
  Підсумки/2026-11.md, 2026.md підсумки місяців і років із посиланнями на нотатки
```

Розділ «Мої доповнення» в кінці нотатки можна редагувати, експорт його зберігає. Нотатку видаленого запису наступний експорт прибирає, якщо її не редагували; інакше залишає й каже про це. Якщо змінити решту нотатки, експорт її пропустить і скаже про це. Зміни з Obsidian назад у базу не потрапляють. Формат: [docs/obsidian-export-format.md](docs/obsidian-export-format.md).

## Дані

- База: `data/media.sqlite` (або `DB_PATH`), обкладинки — `data/covers/`. Перед міграцією на v3 створюється копія `*.pre-v3.sqlite`.
- При старті бот прибирає tracking-параметри зі старих URL і чистить службові записи вже оброблених повідомлень.
- Щоденник — окрема БД `data/journal.sqlite` (або `JOURNAL_DB_PATH`), бот пише в неї записи з `/diary` (чернетка теж у ній). Одноразовий імпорт нотаток `ДД.ММ.РР.md` з Obsidian і перевірка: [docs/journal-import.md](docs/journal-import.md). Backup на Mac і знімок перед деплоєм включають її, коли файл існує.
- Копія щоденника в Obsidian — вручну, раз на тиждень, на Mac: `npm run journal:pull` (спершу можна `-- --dry-run`). Скрипт по SSH (`BACKUP_HOST`, як для backup) просить сервер записати нові записи бота у `data/journal-export/` (`npm run journal:export`, або `JOURNAL_EXPORT_DIR`), а тоді `rsync --ignore-existing` копіює їх у `$OBSIDIAN_VAULT_PATH/Journal` (або `JOURNAL_VAULT_DIR`) і звіряє SHA-256. Імена як у наявних нотатках, `ДД.ММ.РР.md`; другий запис за день — `ДД.ММ.РР (2).md`. Текст — дослівно, без frontmatter. Нотатку, що вже є у vault, скрипт не перезаписує, лише пише, якщо вона відрізняється (правка в Obsidian); правки назад у БД не потрапляють. Запис, видалений у боті, на сервері переходить у `journal-export/.deleted/` і більше не копіюється; з vault нічого не видаляється. Повторний запуск нічого не дублює.
- `npm run export` — JSON і Markdown snapshot у `exports/<timestamp>/`.
- Backup сервера на Mac: у `.env` на Mac задай `BACKUP_HOST` (ім'я Tailscale), далі `npm run backup` (одноразово, `-- --force` ігнорує інтервал) або `npm run backup:install` (щодня о 12:00 і при вході перевіряє, чи минуло 7 днів; зберігається 12 копій у `~/Backups/media-reflection/`). Копія — узгоджений знімок бази (`VACUUM INTO`, бот не зупиняється) і `covers/`; перед тим як лишити її, скрипт відкриває базу й перевіряє `integrity_check`. `.env` не копіюється: токени відновлюються. SSH-ключ має працювати без пароля (ключ у Keychain/агенті). `npm run backup:status` показує останню копію.
- Деплой: push у `main` запускає GitHub Actions (`npm run check`, `npm test`), потім по SSH [deploy/deploy.sh](deploy/deploy.sh) на сервері: fast-forward до протестованого коміту, знімок бази `data/media.sqlite.pre-deploy`, перезапуск сервісу, перевірка через 15 с, відкат на попередній коміт при збої. Налаштування сервера й секретів — у [specs/07-decisions.md](specs/07-decisions.md).
- `TIMEZONE` за замовчуванням `Europe/Prague`.

```sh
npm test
npm run check
npm run format
```

Ще не зроблено: видалення записів, імпорт старих Taste-нотаток, синхронізація з Obsidian в обидва боки, хостинг 24/7.
