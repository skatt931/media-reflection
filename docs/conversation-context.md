# Контекст розмови для Codex

Це **структурований виклад** поточної розмови, не дослівний експорт чату. Не видавай гіпотези з розмови за остаточні технічні рішення.

## Потреба користувача

Користувач хоче краще усвідомлювати, який контент споживає: YouTube, Spotify, Instagram, відеоігри, музичні альбоми, статті та довільний текст. Бажає фіксувати думки, пояснення позитивної чи негативної оцінки, дати та мати зручну історію й добірки. Вхід має бути максимально швидким, з телефону, у тому числі голосом.

## Запропонований сценарій

1. Користувач ділиться посиланням або надсилає повідомлення в Telegram-бот; може одразу додати відгук або залишити на потім.
2. AI збагачує запис доступними метаданими і визначає категорію.
3. Щоранку близько **08:30** бот надсилає список учорашніх збережень і запитує необов'язкову рефлексію (оцінити / пізніше / пропустити). Часовий пояс: імовірно Europe/Prague, підтвердити.
4. Дані зберігаються в структурованому форматі, бажано Obsidian vault (Markdown + YAML frontmatter).
5. Окремий web app на React/TypeScript відображає медіатеку: картки, пошук, категорії, фільтри, рейтинги, власні нотатки, статистику.
6. Згодом можлива щотижнева добірка та аналіз власних смаків.

## Обговорені технології

- Telegram Bot API як інтерфейс збору і запитань.
- n8n як конструктор workflow. n8n Cloud вважається задорогим для цього сценарію; бажана self-hosted Community Edition або простий serverless backend.
- VPS для постійного n8n (можливість запускати також Node.js, Docker, сайти та сервіси синхронізації). Обговорювали Oracle Cloud Free, OVHcloud, Hetzner; цифри з попередніх відповідей не вважати перевіреними поточними цінами.
- Obsidian локально для редагування та перегляду Markdown-файлів. GitHub private repository як Git-версіонування і можливий канал синхронізації.
- React/TypeScript web UI; потенційний хостинг Cloudflare Pages або Vercel.
- GitHub як центральне сховище можливий для невеликого обсягу записів, але не повноцінна транзакційна БД.
- CouchDB + Self-hosted LiveSync розглядалось як альтернативний механізм синхронізації Obsidian, а не як необхідний компонент.

## Обмеження та ризики

- Користувач поки не має власного VPS і хоче максимальну економію.
- Git-синхронізація Obsidian на iPhone може бути менш стабільною, можливі merge-конфлікти та обмежений background sync.
- Приватний vault не можна просто збирати в публічні статичні файли, які доступні будь-кому; не можна вбудовувати GitHub access token у frontend.
- Автоматична ранкова розсилка потребує scheduler, що працює незалежно від відкритого телефону чи ноутбука.
- Зовнішні сервіси не завжди дозволяють отримати всі метадані або вміст через публічні API; graceful fallback важливий.
- Обсяг рефлексії має бути малим, інакше виникне втома від сповіщень.

## Що вже ухвалено, а що ні

**Намір користувача:** Telegram capture + AI категоризація + ранкова рефлексія + довгострокове збереження, потенційно Obsidian + GitHub + вебінтерфейс.

**Не ухвалено:** GitHub чи database як source of truth; VPS чи serverless; точний формат schema; auth у вебзастосунку; Obsidian Git чи LiveSync; момент створення вебзастосунку; інструмент AI/STT; спосіб deduplication.
