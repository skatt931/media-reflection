# Щоденник: БД та одноразовий імпорт з Obsidian

Issue #6. БД щоденника — `data/journal.sqlite` (`JOURNAL_DB_PATH`), окремо від `media.sqlite`: незалежні backup і доступ. Схема в [src/journal.ts](../src/journal.ts), міграції лише адитивні (`PRAGMA user_version`; новіша версія БД, ніж знає код, — помилка).

## Схема v1

Таблиця `journal_entries`:

| Поле | Зміст |
|---|---|
| `id` | автоінкремент |
| `entry_date` | `YYYY-MM-DD`; для імпорту — з назви файла, для бота — день запису |
| `body` | текст; для імпорту — вміст файла дослівно (заголовок і текст як є, байти не змінюються) |
| `source` | `import` або `bot` — так відрізняються імпортовані записи від нових |
| `source_name` | для імпорту — ім'я файла (унікальне серед `import`, на цьому тримається ідемпотентність) |
| `body_sha256` | SHA-256 тексту; для імпорту дорівнює SHA-256 файла |
| `created_at`, `updated_at` | UTC ISO, коли рядок записано/змінено |

Дата не унікальна: у бота може бути кілька записів за день.

## Правила імпорту

- Імпортуються лише файли `ДД.ММ.РР.md` (нуль на початку необов'язковий: `8.07.26.md`; рік `26` → 2026). Дата має існувати в календарі.
- Інші назви пропускаються й виводяться в звіті. Підпапки не читаються.
- Два файли з тією самою датою (`08.07.26.md` і `8.07.26.md`): імпортується перший, другий у звіті.
- Файл не в UTF-8 не імпортується (не псуємо текст).
- Повторний запуск нічого не дублює. Файл, змінений після імпорту, **не перезаписується** — його видно у звіті й у `verify`. Після імпорту джерело правди — БД і бот.

## Покрокова інструкція

Усе, що позначено **Mac**, виконується в терміналі на Mac; **Сервер** — після `ssh media-reflection` (аліас у `~/.ssh/config`, користувач `ihor`). Очікується **33** файли.

### 0. Код має бути на сервері

Код імпорту потрапляє на сервер через деплой: PR з гілки → merge у `main` → GitHub Actions (`check`, `test`) → автодеплой. Перевірка на **Сервері**:

```sh
cd ~/media-reflection && git log --oneline -1 && ls scripts/import-journal.ts
```

Файл `scripts/import-journal.ts` має існувати. Якщо ні — деплой ще не пройшов.

### 1. Mac: подивитися, що буде перенесено

Підстав свій шлях до vault у змінну (папка з `.obsidian` всередині; перевір, що `ls` показує нотатки):

```sh
JOURNAL="/шлях/до/vault/essential/Journal"
ls "$JOURNAL" | head
```

Пробний запуск rsync нічого не копіює, лише показує список. Фільтр бере тільки файли виду `ДД.ММ.РР.md` — три нотатки з вільними назвами на сервер не потраплять:

```sh
rsync -avc --dry-run --include='[0-9]*.[0-9]*.[0-9][0-9].md' --exclude='*' \
  "$JOURNAL/" media-reflection:journal-import/
```

У списку має бути 33 файли, серед них `8.07.26.md`. Якщо кількість інша — зупинись і подивись, які назви не підійшли.

### 2. Mac: скопіювати

Та сама команда без `--dry-run`:

```sh
rsync -avc --include='[0-9]*.[0-9]*.[0-9][0-9].md' --exclude='*' \
  "$JOURNAL/" media-reflection:journal-import/
```

`-c` порівнює файли за контрольною сумою, тож пошкоджена передача не пройде непоміченою. Оригінали не змінюються.

### 3. Сервер: імпорт

```sh
ssh media-reflection
cd ~/media-reflection
npm run journal:import -- ~/journal-import --dry-run   # очікується: Додано: 33
npm run journal:import -- ~/journal-import             # справжній імпорт
npm run journal:verify -- ~/journal-import             # очікується: Файлів 33, записів 33, «Збігається»
```

Якщо `verify` пише `РІЗНИЦЯ …` — імпорт не вважати завершеним, надішли вивід мені. Повторний `journal:import` безпечний: покаже «Додано: 0, уже були: 33».

### 4. Mac: незалежна перевірка проти оригіналів

Порівнює контрольні суми з БД на сервері з контрольними сумами самих оригіналів на Mac. Порожній вивід = збігається:

```sh
diff \
  <(ssh media-reflection 'cd media-reflection && npm run -s journal:manifest' | sort -k2) \
  <(cd "$JOURNAL" && shasum -a 256 [0-9]*.[0-9]*.[0-9][0-9].md | sort -k2) \
  && echo "ОК: 33 записи збігаються з оригіналами"
```

### 5. Прибрати тимчасову папку

Лише після успішних кроків 3 і 4:

```sh
ssh media-reflection 'rm -r ~/journal-import'
```

### 6. Mac: backup із щоденником

```sh
npm run backup -- --force
tail -n 3 ~/Backups/media-reflection/backup.log
```

В останньому рядку має бути `записів щоденника 33, integrity ok`. Backup щоденника має працювати й бути перевіреним до першого запису через бота (issue #3).

## Backup

`scripts/backup.mjs` знімає `journal.sqlite` разом з `media.sqlite` (`VACUUM INTO`, без зупинки бота), перевіряє `integrity_check` і рахує записи; якщо файла ще немає — пропускає без помилки. `deploy/deploy.sh` так само робить `journal.sqlite.pre-deploy`.
