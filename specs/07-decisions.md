Фільтр типу лишається, тільки якщо тип названо в запиті («ресурси», «музика» = трек + альбом). Без embeddings. Без Groq — пошук за словами, ≤10 |

| За типом | «Бібліотека» → «За типом»: лише наявні типи з кількістю → звичайний список зі стрілками |
| Obsidian | Окрема папка `Медіатека` у vault `essential`. Одна нотатка на матеріал з усіма враженнями. Розділ «Мої доповнення» зберігається. Ручні правки решти → конфлікт без перезапису. Taste не чіпаємо й не імпортуємо |
| Ідеї та щоденник (узгоджено 2026-11-08; запис у боті й доставка у vault реалізовано 2026-11-09 (#7, #8), ідеї — 2026-11-09, #9) | Дві окремі сутності, не частина медіатеки: не потрапляють у «Без вражень», підсумки тижня/місяця/року й пошук по матеріалах. **Щоденник**: бот лише збирає текст і віддає у vault, читання й редагування — в Obsidian (джерело правди для редагування). Окрема SQLite-БД (незалежні backup і доступ). Існуючий щоденник з Obsidian імпортується один раз з Mac; після цього нові записи пишуться лише в боті (узгоджено 2026-11-08). У тижневому підсумку — один рядок «останній запис щоденника — N днів тому». Obsidian лишається копією для читання (rsync на Mac, далі наявна синхронізація з iPhone); зміни там у БД не повертаються. Читання (етап 1) і додавання нових записів (пізніше) — також через Telegram Mini App, див. рядок «Mini App». Без AI-обробки за замовчуванням; голосові в Groq — лише за явним вибором. Без нагадувань: ритм раз на тиждень або рідше. Довгий текст — через режим збору (ліміт Telegram ~4096 символів): `/diary` відкриває режим, кілька повідомлень або голосових склеюються в один запис, завершення — кнопка «Готово»; якщо забули, запис зберігається сам після години тиші (не губиться). Дата за замовчуванням сьогодні, з можливістю вказати іншу. **Доставка у vault:** бот на сервері створює нові `.md` у папці експорту, Mac забирає їх (rsync через SSH/Tailscale) без перезапису наявних файлів — конфліктів з ручними правками немає. Частота: раз на тиждень, спочатку вручну; автоматичний запуск (`launchd` на Mac) — пізніше. Головне — щоб файли надходили на Mac; синхронізація Mac ↔ iPhone вже працює поза ботом. Імена як у наявному щоденнику: `ДД.ММ.РР.md`; кілька записів за день допускаються (суфікс на кшталт `(2)`), хоча раніше такого не було. **Передумова:** backup запущено й перевірено до першого запису щоденника |
| Mini App (узгоджено 2026-11-08; каркас реалізовано 2026-11-09, #10; медіатека — 2026-11-09, #12) | Telegram Mini App для щоденника, медіатеки та ідей. Етап 1 — лише перегляд; пізніше — додавання (щоденник, ідеї) і редагування записів медіатеки. Стек: React/TS. Доступ через Tailscale без публічного URL (`tailscale serve` з HTTPS-сертифікатом `*.ts.net`), працює лише коли Tailscale ввімкнений на пристрої. Сервер перевіряє `initData` (HMAC з токеном бота, `auth_date`, user ID = `TELEGRAM_USER_ID`) попри закриту мережу. Перевірено 2026-11-08 (#4) тестовою сторінкою через `tailscale serve`: Telegram iOS з увімкненим Tailscale відкриває Mini App, `initData` приходить (553 символи, user ID власника); з вимкненим Tailscale — порожній екран без пояснення. На Mac Mini App не потрібен (Mac не в tailnet), Desktop і Web не перевірялись. `tailscale serve` для папки чи файлу потребує root; для порту достатньо прав оператора (`ihor` — оператор). HTTP-сервер — усередині процесу бота (один процес і юніт, спільний код і БД), слухає лише `127.0.0.1`, назовні його виставляє `tailscale serve`; розділити процеси, якщо UI виросте або його збої почнуть зачіпати бота. Екрани етапу 1: щоденник — список за датою (новіші зверху), повний текст запису, пошук за словами; медіатека — картки з обкладинкою, фільтри за типом, станом і реакцією, пошук, деталі з усіма враженнями; ідеї — список за датою й пошук за словами. Статистика з графіками й AI-пошук — не в етапі 1. Замінює попередній пункт «Веб-інтерфейс / PWA». **Каркас (#10):** модуль [src/miniapp/](../src/miniapp/): `node:http` у процесі бота, слухає лише `127.0.0.1` (адреса зашита в коді), порт `MINIAPP_PORT` (за замовчуванням 8787, `off` вимикає); збій запуску (зайнятий порт) лише пишеться в лог і бота не зупиняє. `tailscale serve --bg <порт>` виставляє його назовні (перед цим прибрати тестову сторінку з #4: `sudo tailscale serve reset`). Кожен запит `/api/*` має заголовок `Authorization: tma <initData>`; перевірка: HMAC (ключ `HMAC("WebAppData", токен бота)`, рядок із усіх полів крім `hash`), `timingSafeEqual`, `auth_date` не старший за 24 год і не з майбутнього (запас 60 с), `user.id` = `TELEGRAM_USER_ID`; усі відмови — однакова відповідь 401. Статика (`miniapp-dist/`) без перевірки: це лише код інтерфейсу; лише GET/HEAD, захист від виходу за папку, CSP (скрипти лише `self` і `telegram.org`). Кнопка меню: якщо задано `MINIAPP_URL`, бот при старті ставить `setChatMenuButton` (лише чат власника). **Фронтенд:** React 19 + TypeScript + Vite у [miniapp/](../miniapp/), три розділи (Щоденник, Медіатека, Ідеї) з навігацією через hash, safe-area з CSS-змінних Telegram (`--tg-safe-area-inset-*`, `--tg-content-safe-area-inset-*`) та `env(safe-area-inset-*)`; тема — власна палітра (див. рядок про етап 1, #11). **Збірка й доставка (узгоджено 2026-11-09):** зібране комітиться в `miniapp-dist/` (`npm run miniapp:build`); `deploy.sh`, ключі й сервер не змінюються, Vite і devDependencies на сервері не потрібні. Перевірка `test` у CI збирає фронтенд і падає, якщо `miniapp-dist/` розходиться із закоміченим. **Медіатека (#12):** [src/miniapp/library.ts](../src/miniapp/library.ts), лише читання, кожен запит після перевірки `initData`. `GET /api/library?q=&type=&status=&reaction=&unreviewed=1` (значення через кому, реакція `none` — без реакції) повертає всі підходящі картки одним списком, без сторінок (для сотень записів це кілька десятків КБ), плюс кількості для швидких фільтрів по всій бібліотеці й назви типів, станів і реакцій з `src/fields.ts` (одне джерело з ботом). Пошук — той самий `retrieve` із `src/search.ts`: закінчення не враховуються, шукає й у думках. «Без вражень» — множина бота (`unreflected`). Порядок: за датою (`consumed_on`, інакше дата збереження), нові зверху, групи за місяцями. `GET /api/library/<id>` — деталі зі всіма враженнями (`reflections`), назвою джерела й посиланням лише `http(s)`; назовні йдуть лише поля екранів, службові (`manual_fields`, версії метаданих) — ні. `GET /api/library/<id>/cover` віддає локальну обкладинку; ім'я файла з БД має лишатися всередині `data/covers/`; без `store` усі `/api/library*` відповідають 503. `<img>` не вміє слати заголовок, тому фронтенд бере обкладинку через `fetch` з `initData` і показує з blob (CSP `img-src` доповнено `blob:`); обкладинки завантажуються ліниво, без обкладинки — пастельна плитка з першою літерою. Фільтри: тип (кілька), стан (кілька), реакція (кілька й «Без реакції») комбінуються з пошуком; «Улюблене» і «Сподобалось» у шторці окремі (не як у боті, де «сподобалось» включає улюблене). Екран матеріалу — `#/media/<id>`, «Назад» — спільний `useBack` (рідна `BackButton` Telegram). Фільтри й пошук пам'ятаються в модулі, позиція прокрутки — за адресою (`useScrollMemory`), тож повернення зі списку матеріалу лишає все на місці. Вигляд — за макетом A («Editorial», `design/mockups`) на спільних токенах і шторці з #11 **Запис і редагування (#14, узгоджено 2026-11-09):** сервер крім `GET` приймає `POST` і `PATCH` лише на `/api/*` (файли застосунку й `/api/me` — лише читання; `PUT` і `DELETE` немає). Тіло — JSON до 512 КБ; `initData` перевіряється до читання тіла. Усю валідацію робить сервер у [src/miniapp/write.ts](../src/miniapp/write.ts), екрани їй не довіряють; помилка називає лише поле. Повтор того самого тексту протягом двох хвилин (втрачена відповідь, подвійний тап) нічого нового не пише. **Щоденник:** `POST /api/diary` `{date, body}` — дата не майбутня (за `TIMEZONE`), текст до 100 000 символів; запис іде як `source='bot'` і з наступним `journal:export` потрапляє в Obsidian новим файлом, як і записи з бота (окреме джерело не потрібне, міграцію таблиці не робимо). Редагування й видалення записів щоденника в Mini App немає. Екран `#/diary/new`: дата (за замовчуванням сьогодні) і поле, що росте з текстом; чернетка лежить у `localStorage` пристрою, поки не збережено; вихід без збереження й закриття Mini App питають підтвердження. **Ідеї:** `POST /api/ideas` `{body}` до 4 000 символів (джерело `text`, дата й час за `TIMEZONE`). Ідея не видаляється в Mini App: міграція v5 додає `ideas.resolved_at`; `POST /api/ideas/<id>/resolve` і `/restore`. Список віддає відкриті (`ideas`) і вирішені (`resolved`, нещодавно вирішені першими); внизу тієї ж сторінки згорнутий блок «Вирішені · N», звідти ідею можна повернути. Вирішена ідея лишається в експорті в Obsidian (файл у Inbox не чіпається). Уточнено перед впровадженням: фільтрація й пошук на сервері тим самим кодом, що й у боті; один список без сторінок; обкладинки через `fetch` з `initData`, а не через query-параметр (щоб `initData` не потрапляв у адреси).
- **2026-11-09 — Mini App: додавання й редагування.** Новий запис щоденника й нова ідея, «вирішені» ідеї, зміна типу, стану, реакції й тегів матеріалу, нове враження. Уточнено перед впровадженням: редагується те, що в issue, плюс нове враження (без назви, автора, дати й видалення); без підтверджень там, де зміну можна скасувати; запис із Mini App іде тим самим експортом із `source='bot'`, схему щоденника міняємо лише на `ideas.resolved_at`. Експорт змін медіатеки у vault — окремо, #13. Пізніше в тому ж PR: бот узгоджено з Mini App (вирішені ідеї, без видалення).

## Відкрито

- Backup за межами Mac: зашифроване зовнішнє сховище (B2/R2), бо зараз копія з'являється, лише коли Mac увімкнений. Відновлення з копії перевірено тільки відкриттям бази (`integrity_check`), повного сценарію «підняти сервер з backup» немає.
- 2FA на GitHub-акаунті: push у `main` виконує код на сервері від імені `ihor`, тож акаунт — слабка ланка деплою.
- Obsidian-експорт після переносу: БД із обліком експорту (`vault_exports`, `vault_pending`) тепер на сервері, а vault — на Mac. Потрібен спосіб запускати експорт без розходження обліку (наприклад, синхронізація папки `Медіатека`).
- Щоденник: імпорт — 33 датовані нотатки `ДД.ММ.РР.md` у `essential/Journal` (один файл без нуля: `8.07.26.md`), вміст і frontmatter ще не переглянуто; три нотатки з вільними назвами (`Думки вголос..md`, `Просто роздуми.md`, `Роздуми про переїзд.md`) не імпортуються, лишаються лише в Obsidian (узгоджено 2026-11-08); як одноразово передати 33 файли з Mac на сервер (наприклад, rsync через Tailscale у тимчасову папку, імпорт скриптом на сервері); як у БД відрізнити імпортовані записи від нових.
- Mini App: порожній екран при вимкненому Tailscale — чи пояснювати це (наприклад, у тексті кнопки чи довідці). Каркас на сервері ще не виставлено через `tailscale serve` і не перевірено в Telegram після деплою.
- Mini App, етап 2: враження з Mini App не йдуть до AI (теги й опис за ними не оновлюються), а підказок наявних тегів у шторці немає. Запис не перевірено в Telegram на пристрої після деплою.
- Експорт Медіатеки після переносу окремо від щоденника: він читає файл у vault, щоб помітити ручні правки (`src/vault.ts`), тому «сервер пише, Mac копіює» для нього не підходить. Розглядається запуск експорту на Mac по знімку БД з обліком на боці Mac.
- Оновлення Node на сервері вручну (архів із перевіркою суми); автоматичні оновлення ОС налаштовано, Node у них не входить.
- Імпорт Taste, двосторонні правки з Obsidian.
- Embeddings / семантичний пошук (sqlite-vec у тій самій БД). Потребує окремого провайдера embeddings — у Groq його немає. Повернутися, коли записів буде ~1000 або пошук за 30 кандидатами перестане вистачати.
- Аналітика з `src/stats.ts` переїде в Mini App з графіками (замість окремого веб-інтерфейсу/PWA).
- Тривалість матеріалів (години відео/музики) і фіксований словник тем — для точніших підсумків.
