| Ідеї та щоденник (узгоджено 2026-11-08, не реалізовано) | Дві окремі сутності, не частина медіатеки: не потрапляють у «Без вражень», підсумки тижня/місяця/року й пошук по матеріалах. **Щоденник**: бот лише збирає текст і віддає у vault, читання й редагування — в Obsidian (джерело правди для редагування). Окрема SQLite-БД (незалежні backup і доступ). Існуючий щоденник з Obsidian імпортується один раз з Mac; після цього нові записи пишуться лише в боті (узгоджено 2026-11-08). У тижневому підсумку — один рядок «останній запис щоденника — N днів тому». Obsidian лишається копією для читання (rsync на Mac, далі наявна синхронізація з iPhone); зміни там у БД не повертаються. Читання (етап 1) і додавання нових записів (пізніше) — також через Telegram Mini App, див. рядок «Mini App». Без AI-обробки за замовчуванням; голосові в Groq — лише за явним вибором. Без нагадувань: ритм раз на тиждень або рідше. Довгий текст — через режим збору (ліміт Telegram ~4096 символів): `/diary` відкриває режим, кілька повідомлень або голосових склеюються в один запис, завершення — кнопка «Готово»; якщо забули, запис зберігається сам після години тиші (не губиться). Дата за замовчуванням сьогодні, з можливістю вказати іншу. **Доставка у vault:** бот на сервері створює нові `.md` у папці експорту, Mac забирає їх (rsync через SSH/Tailscale) без перезапису наявних файлів — конфліктів з ручними правками немає. Частота: раз на тиждень, спочатку вручну; автоматичний запуск (`launchd` на Mac) — пізніше. Головне — щоб файли надходили на Mac; синхронізація Mac ↔ iPhone вже працює поза ботом. Імена як у наявному щоденнику: `ДД.ММ.РР.md`; кілька записів за день допускаються (суфікс на кшталт `(2)`), хоча раніше такого не було. **Передумова:** backup запущено й перевірено до першого запису щоденника |
| Mini App (узгоджено 2026-11-08, не реалізовано) | Telegram Mini App для щоденника, медіатеки та ідей. Етап 1 — лише перегляд; пізніше — додавання (щоденник, ідеї) і редагування записів медіатеки. Стек: React/TS. Доступ через Tailscale без публічного URL (`tailscale serve` з HTTPS-сертифікатом `*.ts.net`), працює лише коли Tailscale ввімкнений на пристрої. Сервер перевіряє `initData` (HMAC з токеном бота, `auth_date`, user ID = `TELEGRAM_USER_ID`) попри закриту мережу. Перевірено 2026-11-08 (#4) тестовою сторінкою через `tailscale serve`: Telegram iOS з увімкненим Tailscale відкриває Mini App, `initData` приходить (553 символи, user ID власника); з вимкненим Tailscale — порожній екран без пояснення. На Mac Mini App не потрібен (Mac не в tailnet), Desktop і Web не перевірялись. `tailscale serve` для папки чи файлу потребує root; для порту достатньо прав оператора (`ihor` — оператор). HTTP-сервер — усередині процесу бота (один процес і юніт, спільний код і БД), слухає лише `127.0.0.1`, назовні його виставляє `tailscale serve`; розділити процеси, якщо UI виросте або його збої почнуть зачіпати бота. Екрани етапу 1: щоденник — список за датою (новіші зверху), повний текст запису, пошук за словами; медіатека — картки з обкладинкою, фільтри за типом, станом і реакцією, пошук, деталі з усіма враженнями; ідеї — список за датою й пошук за словами. Статистика з графіками й AI-пошук — не в етапі 1. Замінює попередній пункт «Веб-інтерфейс / PWA» |
| Міграції | Адитивні. PRAGMA user_version=3, backup `.pre-v3.sqlite` перед першою міграцією. Старі ручні поля консервативно заблоковані від AI |

## Відкрито

- Backup за межами Mac: зашифроване зовнішнє сховище (B2/R2), бо зараз копія з'являється, лише коли Mac увімкнений. Відновлення з копії перевірено тільки відкриттям бази (`integrity_check`), повного сценарію «підняти сервер з backup» немає.
- 2FA на GitHub-акаунті: push у `main` виконує код на сервері від імені `ihor`, тож акаунт — слабка ланка деплою.
- Obsidian-експорт після переносу: БД із обліком експорту (`vault_exports`, `vault_pending`) тепер на сервері, а vault — на Mac. Потрібен спосіб запускати експорт без розходження обліку (наприклад, синхронізація папки `Медіатека`).
- Ідеї (memory dump): узгоджено в загальних рисах — окрема сутність; пропозиція: команда `/idea текст` або кнопка в меню, один рядок без діалогу, відповідь реакцією ✓, `/ideas` зі списком зі стрілками, бот пише у свою папку (наприклад, `Journal/Ideas/Inbox/`), а не в `Ideas Dump.md`, щоб не конфліктувати з ручними правками. Не вирішено: окрема БД, як у щоденника, чи ні; файл на день чи інша схема в Obsidian.
- Щоденник: імпорт — 33 датовані нотатки `ДД.ММ.РР.md` у `essential/Journal` (один файл без нуля: `8.07.26.md`), вміст і frontmatter ще не переглянуто; три нотатки з вільними назвами (`Думки вголос..md`, `Просто роздуми.md`, `Роздуми про переїзд.md`) не імпортуються, лишаються лише в Obsidian (узгоджено 2026-11-08); папка експорту на сервері й команда pull на Mac; як одноразово передати 33 файли з Mac на сервер (наприклад, rsync через Tailscale у тимчасову папку, імпорт скриптом на сервері); як у БД відрізнити імпортовані записи від нових.
